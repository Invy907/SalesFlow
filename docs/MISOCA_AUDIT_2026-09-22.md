# Misoca 비교 점검 및 수정 기록

점검일: 2026-09-22

## 범위와 판단

Chrome에 로그인된 [Misoca](https://app.misoca.jp/home)의 실제 화면과 SalesFlow의 페이지·서버 액션·DB 정책을 비교했다. Misoca에서는 홈, 문서 4종 목록/작성/상세, 세금·서식 탭, 자동 작성 예약, 수주/주문폼, 리포트, 거래처, 품목, 받은 문서함, 설정을 읽기 전용으로 살펴봤다. Misoca의 고객 데이터 변경, 이메일·FAX·우편 발송, 유료 기능 실행은 하지 않았다.

SalesFlow는 문서 작성의 기본 구조를 갖췄지만, 겉으로 보이는 기능과 실제 저장·연결 동작 사이에 차이가 있었다. 특히 계산 결과의 DB 덮어쓰기, 편집 중 명세 유실 가능성, URL 쿼리 손실, 목록 상태와 권한 문제가 우선 수정 대상이었다. 아래의 수정은 현 작업 트리에 반영되어 있다. 배포나 운영 DB 변경은 하지 않았다.

Misoca 전체 기능과의 완전한 동등성을 의미하지 않는다. 실제 화면으로 확인한 범위, 코드·테스트로 검증한 범위, 연동 환경이 없어 실행하지 않은 범위를 구분했다.

## 주요 비교와 수정

| 영역 | 확인한 문제 | 반영 내용 |
| --- | --- | --- |
| 라우팅 | 언어 경로 재작성 시 검색·필터·복제·견적 변환·인증 쿼리가 사라짐 | URL query를 보존하고 회귀 테스트 추가 |
| 문서 입력 | 탭 이동 시 명세 초기화, 빈 수량 표시와 저장의 불일치 | 탭 상태 유지, 실제 입력 행의 기본수량 1 일치, 빈 행은 0 처리 |
| 세금 | 내세·면세·반올림·원천징수 설정과 DB 합계 불일치 | 화면/서버/DB 계산을 정렬, 소수수량·음수 할인행·혼합세율 처리 |

| 입력 검증 | 잘못된 날짜·빈 문서·금액/수량 정밀도·다른 조직 참조 검증 부족 | 서버 스키마 및 저장 RPC 검증 강화 |
| 납품서·영수증 | 상세에서 편집 경로가 없고 샘플 날짜·회사명이 표시됨 | 편집 페이지/저장 액션 연결, 현재 날짜·회사 기본값 사용 |
| 복제·변환 | 발신자·수신자·세금·서식 일부 누락 | 청구서 복제/견적 변환, 견적→납품서에 원본 스냅샷 보존 |
| 수신자·발신자 | 상세 입력 일부가 실제 저장에 미연결, 자유입력 거래처가 목록에서 빈 값 | 저장/미리보기 연결, 문서 당시 이름을 목록·검색·홈에 반영 |
| 문서 출력 | 세율별 내역 누락, 견적 공유/상세의 표시 요소 차이 | 공통 미리보기 사용, 10%/경감8% 등의 대상액·세액·주석과 원천세 출력 |
| 목록 4종 | 검색/페이지 변경 후 숨은 선택 항목에 일괄 작업 가능 | 현재 표시 항목 기준 선택, 상태 변경 시 초기화, 페이지 범위 보정 |
| 검색 | 거래처명·사내메모·자유입력 수신자 검색 누락, 특수문자 문제 | 필드 검색 및 PostgREST 인자 인용/와일드카드 처리 |
| 청구서 미리보기 | 빠르게 다른 행을 선택하면 이전 응답 표시·로딩 고착 가능 | 요청 식별과 실패/종료 상태 처리 |
| 입금·미수 | 입금 합계 갱신 경쟁, 미입금 집계의 건수 제한 | DB 지급 트리거를 합계의 기준으로 사용, 전체 페이지 집계 |
| 홈·리포트 | API 응답 한도 이후 금액이 합계에서 빠짐, 날짜 경계·수금 상태 불일치 | 명시적 페이지 순회, JST 경계, 운영 미수와 실제 원장 구분 |
| 공개 링크 | 청구서 공개 링크가 로그인으로 막힘 | 토큰 전용 공개 경로 허용, 비공개 문서 경로는 인증 유지 |
| 청구서 CSV | 화면만 있고 생성 흐름이 연결되지 않음 | SalesFlow 전용 템플릿→검증→내용/합계 검토→초안 생성 구현 |
| 거래처·품목 CSV | UTF-8 파일을 Shift-JIS로 잘못 안내, 일본어 가져오기 손상 가능 | 다운로드 인코딩 안내 수정, UTF-8/Shift-JIS 읽기 처리 |
| 주문폼 | 저장되지 않는 UI | 초안 저장·목록·명세 확인·복사·삭제 연결, 공개 접수 미지원 명시 |
| 계정·팀 | 샘플 계정/요금, 고정 멤버 수, 무반응 메뉴 | 실제 프로필·조직·멤버·역할 표시, 표시이름 수정 및 로그아웃 연결 |
| 권한 | 다른 멤버의 조직 역할이 선택될 가능성, viewer의 업무 데이터 수정 허용 | 현재 사용자 조건 추가, viewer 쓰기 RLS 및 서비스권한 우회 경로 차단 |
| 이용 내역 | 샘플 청구서 수·무료 한도·요금·업그레이드 UI | 실제 당월 생성 건수, 과금 연동 미지원 안내 |
| 미지원 기능 | FAX·일부 설정·문의가 실행 가능한 기능처럼 보임 | 지원 범위를 명시하고 거짓 성공/문의 링크 제거 |
| 배치·사용성 | 기본 화면을 크게 차지하는 AI 패널, 세율 팝업 잘림, 메뉴 키보드 동작 부족 | AI 기본 접힘, 네이티브 세율 선택, 포커스/Escape·모달·모바일 메뉴 개선 |

## 계산과 상태의 기준

- 문서 합계는 명세, 세금 표시 방식, 세율, 반올림, 원천징수 설정을 함께 적용한다. 납품서의 청구 시 세금 계산 설정도 분리한다.
- 할인은 음수 단가의 명세로 표현할 수 있다. 문서 전체 소계가 음수가 되는 입력은 허용하지 않는다.
- 수량은 최대 소수점 4자리로 검증하고, JavaScript 부동소수점 오차가 최종 엔 금액에 영향을 주지 않도록 계산한다.
- 상세·공유·인쇄용 미리보기·Excel의 세금 내역은 같은 요약 함수를 사용한다.
- 청구서의 수동 **입금 표시**와 실제 **입금 원장**은 기존 설계대로 별개다. 홈/미수/수금예정에서는 입금 표시된 청구서를 제외한다. 월별 입금액과 매출채권 원장은 실제 `payments`/`paid_amount`를 사용한다. 수동 표시만 바꿔 실제 입금 기록을 생성하지 않는다.
- 우편 발송 버튼은 실제 배송이 아니라 발송 완료를 기록한다는 문구로 수정했다.

## 검증 기록

### 실제 Chrome + 격리 로컬 DB

운영 연결 정보가 없는 상태에서 별도의 로컬 Supabase 프로젝트와 합성 QA 계정/문서를 사용했다. 기존에 실행 중이던 다른 프로젝트 DB는 변경하지 않았다.

| 시나리오 | 확인 결과 |
| --- | --- |
| 로그인 및 홈 | 로그인 성공, 실제 문서 금액·수신자·각 상세 링크 표시 |
| 견적 작성/탭 전환 | 명세 유지, 수량 3 × 단가 101의 내세·올림: 합계 303, 포함세액 28 저장/출력 일치 |
| 견적→청구서 | 원본 수신자·명세·세금 설정으로 작성, 합계 303 저장 |
| 자유입력 수신자 | 청구서 목록 및 홈에 저장한 이름 표시 |
| 납품서 작성/편집 | 작성 후 번호·발신자·수신자 보존, 수량 변경과 경감8% 행 추가 후 합계 6,030 |
| 혼합세율 출력 | 10% 대상 4,500/세액 450, 경감8% 대상 1,000/세액 80, 총세액 530 확인 |
| 영수증 작성/편집 | 빈 수량을 1로 계산, 2,200 저장 후 단가 변경하여 2,750, 번호·발신자 유지 |
| 모바일 390×844 | 목록, 메뉴 이동, 문서 상세, 납품서 입력, 탭과 고정 저장영역 확인; 이후 viewport 원복 |
| 계정/팀 | 실제 프로필 저장 성공, 실제 조직·멤버 수·본인 역할 표시, 로그아웃 후 로그인 화면 이동 |
| 공개/비공개 경로 | 쿠키 없이 유효한 견적 공유 200, 존재하지 않는 청구서 공유 404, 비공개 청구서 목록은 로그인 이동 |
| CSV | 화면·파서·검증·생성 코드 검사. Chrome 확장 로컬 파일 접근 제한으로 파일 선택부터 끝까지의 브라우저 실증은 미완료 |

CSV 파일 선택 실증을 진행하려면 Chrome의 ChatGPT 확장 설정에서 파일 URL 접근을 허용해야 한다. [공식 안내](https://developers.openai.com/codex/app/chrome-extension#upload-files).

### 자동 검사

- `npm test`: 최종 결과는 아래 실행 요약 참조.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`, `git diff --check` 실행.
- `supabase/tests/document_saves.sql`: 문서 4종 저장/수정, 세금 계산, 실패 시 원본 보존, 잘못된 조직 참조, 지급 집계 검증.
- `supabase/tests/organization_memberships.sql`: 현재 사용자의 실제 역할과 같은 조직 멤버 조회 검증.
- `supabase/tests/viewer_business_permissions.sql`: viewer 읽기/쓰기 차단, member/admin/owner 쓰기, 타조직 접근·채번 거부, service_role 작업, 본인 프로필/알림 동작 유지 검증.
- SQL 테스트 데이터는 트랜잭션 종료 시 롤백했다.

## DB 적용 사항

코드 배포 전에 다음 마이그레이션이 필요하다.

1. `0032_document_calculation_and_atomic_save.sql`: 원천징수 저장 컬럼, 합계/세금 재계산, 원자적 문서 저장 RPC, 입금 집계.
2. `0033_viewer_business_write_restrictions.sql`: 조직별 업무 쓰기 권한, 파일 접근, 채번 및 RPC 권한 보정.

**0032는 기존 문서 합계도 다시 계산한다.** 운영 DB에 적용하기 전 백업과 복제 DB에서 기존 발행 문서의 변경 금액을 대조해야 한다. 이번 작업에서는 합성 데이터가 있는 격리 로컬 DB에만 적용했다. 운영 데이터에 대한 금액 차이 검증·마이그레이션·배포는 수행하지 않았다.

## 남은 기능 차이와 검증 한계

| 항목 | 현재 범위 / 다음 구현 기준 |
| --- | --- |
| Misoca 전체 서식 | 기본 서식/설정은 유지하지만 모든 템플릿, 자유로운 열 제목·배치 커스터마이징과 동등하지 않음 |
| 공개 주문폼 | 초안 관리만 구현. 공개 URL·고객 주문접수·접수 알림·수주 전환은 별도 구현 필요 |
| FAX/물리 우편/결제/회계 | 외부 사업자·회계 연동 미구현. 실제 사용 가능한 것처럼 표시하던 부분은 교정 |
| 팀 관리 | 실제 멤버 조회 및 DB 권한 적용. 멤버 초대·권한 변경 UI는 별도 구현 필요 |
| Misoca CSV 호환 | 새 청구서 CSV는 SalesFlow 전용 계약. Misoca 내보내기 파일을 그대로 읽는 호환성은 보장하지 않음 |
| 청구서→영수증 | 직접 영수증 작성·편집과 거래처 진입은 지원. 청구서에서 영수증으로 변환하는 전용 UI는 없음 |
| Gmail·정기 실행·AI | 기존 구현과 관련 회귀 테스트를 확인했지만 실제 Gmail 발송, OAuth 재연결, cron 운영, 유료 AI 실행은 검증하지 않음 |
| 다국어 | 주요 업무 화면은 3언어 제공. 인증 화면 등 일부 일본어 고정 문구의 전체 번역은 남아 있음 |
| PDF·인쇄 | 공통 출력 렌더와 세율 표시를 확인. 실제 프린터 출력 및 긴 80행 문서의 모든 페이지 조합 실증은 수행하지 않음 |
| 대규모 집계 | 행 수 절단은 제거. 큰 조직에서는 DB 집계 RPC/인덱스 및 성능 측정이 다음 최적화 대상 |
| 오류/빈 상태 | 확인된 흐름은 보정했지만 모든 브라우저·동시사용·네트워크 실패 조합을 전수 검증한 것은 아님 |

외부 서비스 계약·운영 채널·차별화 정책이 필요한 기능은 임의로 연결하지 않았다. 기본 문서 흐름의 신뢰성을 먼저 바로잡고, 미지원 영역을 실제 기능으로 오해하지 않도록 표시했다.

## 최종 실행 요약

- 단위/회귀 테스트 **118개 통과**, 실패·건너뜀 없음.
- 전체 ESLint 통과, TypeScript 검사 통과.
- Next.js 16.2.6 프로덕션 빌드 성공: 정적 페이지 145개 생성 완료, 동적 라우트 포함.
- DB 회귀 스크립트 3종 통과 후 rollback 확인.
- `git diff --check` 통과.
- 임시 로컬 검증용 환경파일과 서비스는 검사 후 정리했다. 원래 프로젝트에 운영 환경변수는 없었으므로 실제 사용에는 별도 Supabase 연결 설정이 필요하다.
